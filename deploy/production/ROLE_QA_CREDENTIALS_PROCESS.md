# Getting authorized QA credentials for Superadmin, Admin, Master Agent, Agent (administrator-operated)

Status 2026-11-13: only the player QA account (`uat_player5`) exists in the local credential files and works on production.
UAT accounts are not assumed to exist in production (they share one database, but each account must still be proven by a real sign-in).

## Rules
- Never recover passwords from hashes or SQL files. Never reset or unlock a live customer/staff account without the owner's approval.
- Do not touch balances, transactions or game configuration. QA staff accounts hold no money and are never given balance adjustments.
- Credentials stay in a local file outside the repository (`%USERPROFILE%\maxhigh-uat-secrets\role-qa.tsv`). Claude never sees them.

## Step 0 — Check whether usable staff accounts already exist (read-only, no passwords)
Sign in as the owner at https://maxhigh.online/superadmin/login (the owner account in the handover, `client_owner`) and open
`/superadmin/admins`. Note which usernames exist for roles admin, master_agent, agent. If you already own QA-designated staff
accounts, put them in `role-qa.tsv` with `New-RoleQaFile.ps1` (only if they appear in your local credential files) or add lines by hand.
If `client_owner`'s password is not known or the account is marked "requires secure reset", the OWNER must complete that reset
themselves (or approve it explicitly in writing); nobody else should reset it.

## Step 1 — QA staff accounts (owner approval received 2026-11-13 for qa_admin, qa_master_agent, qa_agent)
Findings from the code that change the plan:
- The Super Admin screen (`/superadmin/admins` → "+ Add Agent") can create **agent, master_agent and superadmin** only. The `/admin/users` create modal offers player/agent/master_agent.
  **No application screen creates an `admin` role**, and accounts must not be inserted directly. So `qa_admin` cannot be created through the approved route.
  Options: (a) the owner supplies an existing admin account for QA; (b) the owner approves a separate, reviewed change (a developer task, not a database insert); (c) mark Admin "PENDING — no creation path" in the report.
- Staff accounts count toward the client-account cap (`activeClientFilter`: client accounts with role != player, excluding accounts locked by staff). Creation is refused at the cap and the cap is never bypassed; locking the QA accounts afterwards frees the slots.
- Super Admin creation always uses starting balance 0; no chips are added.

Create `qa_master_agent` and `qa_agent` with the reviewed script (passwords generated by the script, never shown; it needs a `superadmin` line in the local file):
```powershell
$env:ROLE_QA_CREDENTIALS_FILE = "$env:USERPROFILE\maxhigh-uat-secrets\role-qa.tsv"
node --test deploy/production/qa-staff-plan.test.mjs   # logic regression tests (no browser/credentials)
node deploy/production/create-qa-staff.mjs            # DRY RUN: validates each form independently, creates nothing (upline shows PENDING UNTIL APPLY)
node deploy/production/create-qa-staff.mjs --apply    # creates qa_master_agent, then qa_agent (upline = qa_master_agent)
```
It appends `master_agent` and `agent` lines to the same file after each creation succeeds, records usernames (no passwords) in
`output/production-role-acceptance/created-qa-accounts.json`, and stops at the first problem. If a sign-in fails it stops without trying again.
If the owner's password is unknown, the owner must reset it themselves or approve a reset in writing (nobody else resets it).

## Step 2 — Run the acceptance test
```powershell
$env:ROLE_QA_CREDENTIALS_FILE = "$env:USERPROFILE\maxhigh-uat-secrets\role-qa.tsv"
node deploy/production/verify-roles.mjs
Remove-Item Env:ROLE_QA_CREDENTIALS_FILE
```
Send `output/production-role-acceptance/report.json` (it lists blocked request kinds by method + path only).

## Step 3 — Afterwards (ask the owner before locking)
Lock or disable the `qa_*` accounts in `/superadmin/admins` (do not delete: audit/ledger history must stay intact), or keep them with the
passwords in the encrypted handover for future regression runs. Delete `role-qa.tsv` if no longer needed.
