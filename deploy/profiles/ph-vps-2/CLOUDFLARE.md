# Cloudflare and Caddy compatibility

Reporting date: 2026-11-09 (Asia/Shanghai). Evidence files retain their machine-generated UTC timestamps. No production deployment, real player changes, live Cloudflare changes or credential rotation were performed.

The profile Caddyfile is prepared, not installed. Its syntax was adapted with a checksum-verified official Caddy executable; this is not certificate loading, real origin verification or a live zone change. TLS paths and domain must be provisioned privately. Current ranges were read from [Cloudflare's public IP endpoint](https://api.cloudflare.com/client/v4/ips); review both IPv4/IPv6 before installation and after provider changes. No account API token was used.

Use [Full (strict)](https://developers.cloudflare.com/ssl/origin-configuration/ssl-modes/full-strict/) with a valid origin certificate. Restrict origin ingress to reviewed Cloudflare ranges at the firewall and the Caddy remote-peer matcher. Restrict SSH separately; never expose 3306, 8080, updater 9090, PM2 sockets or Caddy admin 2019. Loopback readiness/metrics stay private. Test direct-origin denial over IPv4 and IPv6. Add authenticated, preferably zone-specific origin access where supported; IP allowlisting alone is not proof that a request belongs to this zone. Certificate/account access and rotation remain operator gates.

[Caddy trusted proxies](https://caddyserver.com/docs/caddyfile/options#trusted-proxies) are restricted to those ranges, use strict forwarding interpretation and normalized client IP forwarding. Do not trust a caller-supplied CF-Connecting-IP from an untrusted origin peer. The profile strips that upstream header after producing verified X-Real-IP/X-Forwarded-For values. Validate actual client-IP behavior with authorized edge/origin requests before enabling IP-based security decisions.

Cache only generated fingerprinted /assets/ files with successful public JS/CSS/media responses. Retain browser immutable caching only where names identify content; ordinary /games/ paths are not automatically immutable merely because a directory has a date. Bypass all authenticated HTML, mh_session cookies, /_serverFn/, /api/, staff/account and financial paths. Never create a broad Cache Everything rule. Verify two separate users cannot receive each other's content and that private,no-store survives the edge. No live CDN hit rate or cache test was available.

Start WAF/bot protections in a reviewed monitor mode. Test login-specific throttling and account recovery; do not challenge or blanket-throttle financial JSON RPCs in a way that returns HTML or blocks legitimate fishing rates. Shared-IP/NAT traffic and shot cadence make a single tiny per-IP limit unsafe. Login RPC fingerprints change with builds, so match the actual release and rehearse rule updates. App RBAC, idempotency and validation remain authoritative.

No active server WebSocket implementation was found in the reviewed application; current real-time UI uses polling. Caddy reverse proxy can support upgrades if a future authenticated WebSocket service is introduced; qualify Cloudflare idle/heartbeat behavior then. No updater route is publicly proxied by this profile.
